## Technical Documentation Overview

### Purpose
Technical documentation demonstrates that the device meets the General Safety and Performance Requirements (GSPR) and supports conformity assessment.

### Who Needs It
- All device classes require technical documentation
- Level of detail increases with device risk class
- Class III requires most comprehensive documentation

### Maintenance Requirements
- Must be kept up-to-date throughout device lifecycle
- Updates required for design changes
- Must be available for competent authority review

## Annex II Structure

### Section 1: General Information

#### 1.1 Device Identification
- Device description and overview
- All intended purposes and claims
- Patient population
- Basic UDI-DI assignment
- Manufacturing information

#### 1.2 Manufacturer Information
- Legal manufacturer name and address
- Authorized representative details
- Manufacturing site information
- Quality management system certification

#### 1.3 Reference Information
- Previous submissions (if any)
- Reference to equivalent devices
- Notified Body certificate number

### Section 2: Device Description

#### 2.1 Device Description and Specification
- Complete device description
- All variants and configurations
- Accessories included
- Software specification (if applicable)
- Materials and components

#### 2.2 Reference to Previous Generations
- Comparison with previous versions
- Changes implemented
- Reason for changes

#### 2.3 Product Lifecycle
- Design and development history
- Manufacturing history
- Distribution and storage
- End of life considerations

### Section 3: General Safety and Performance Requirements

#### 3.1 GSPR Checklist
- Systematic approach to Annex I requirements
- Compliance demonstrated for each requirement
- Methods used to demonstrate compliance

#### 3.2 Benefit-Risk Analysis
- Clinical benefits documented
- Residual risks identified
- Benefit-risk ratio justification
- Risk acceptability criteria

### Section 4: Risk Management

#### 4.1 Risk Management File
- Risk management plan
- Risk analysis (identification, estimation)
- Risk evaluation
- Risk control measures
- Residual risks
- Benefit-risk determination
- Risk management report

### Section 5: Clinical Evaluation

#### 5.1 Clinical Evaluation Report (CER)
- Clinical evaluation plan
- Scope of evaluation
- Clinical data sources
- Appraisal of clinical data
- Analysis of clinical data
- Conclusions on clinical evidence
- PMCF plan integration

### Section 6: Design and Manufacturing

#### 6.1 Design and Development
- Design and development process
- Design inputs
- Design outputs
- Design verification
- Design validation
- Design transfer
- Design changes

#### 6.2 Manufacturing Process
- Manufacturing processes described
- Process validation
- Critical processes identified
- Sterilization processes (if applicable)

### Section 7: Product Verification and Validation

#### 7.1 Pre-Clinical Data
- Bench testing results
- Biocompatibility testing
- Software validation
- Electrical safety testing
- EMC testing (if applicable)

#### 7.2 Clinical Data
- Clinical investigations
- Literature data
- Post-market data

### Section 8: Labeling and Instructions

#### 8.1 Labeling
- Device label content
- Packaging labels
- UDI carrier
- Language requirements

#### 8.2 Instructions for Use
- Intended users
- Clinical use instructions
- Contraindications and warnings
- Maintenance and storage
- Any relevant residual risks

## Annex III PMS Documentation

### PMS Plan Requirements (Article 84)

#### 1.1 Proactive Surveillance
- Systematic process to collect post-market data
- Sources of data
- Data to be collected
- Frequency of collection
- Responsibilities

#### 1.2 Reactive Surveillance
- Complaint handling procedures
- Incident reporting procedures
- Trend reporting mechanisms

#### 1.3 PMCF Integration
- PMCF activities
- PMCF evaluation schedule
- Integration with clinical evaluation

### Periodic Safety Update Report (PSUR)

#### Report Content
- Device summary
- Sales and production data
- Incident analysis
- Benefit-risk conclusion
- PMCF conclusions
- Overall conclusions

#### Reporting Frequency
- Class III/IIb: Every 2 years (or as required by NB)
- Class IIa/I: Every 5 years (for Class IIa with NB involvement)

## Common Deficiencies

### Top Issues Identified by Notified Bodies

1. **Incomplete GSPR Checklist**
   - Missing compliance demonstration
   - Vague compliance statements
   - Missing reference to evidence

2. **Risk Management Issues**
   - Not aligned with ISO 14971
   - Missing residual risk evaluation
   - Benefit-risk not clearly documented

3. **Clinical Evaluation Gaps**
   - Literature search inadequate
   - Equivalence not properly justified
   - PMCF not adequately planned

4. **Technical Documentation Organization**
   - Poor document structure
   - Missing cross-references
   - Version control issues

5. **Verification and Validation**
   - Incomplete testing documentation
   - Missing acceptance criteria
   - Validation protocols not followed

### Best Practices

1. **Start Early**: Begin documentation during development
2. **Use Templates**: Ensure consistent structure
3. **Cross-Reference**: Link related documents
4. **Review Regularly**: Keep documentation current
5. **Train Team**: Ensure everyone understands requirements
